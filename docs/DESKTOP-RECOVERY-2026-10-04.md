# E-Rx cells disappear in an otherwise valid entry window

The October 4 desktop report selected one valid Framework entry window. Its visible E-Rx grid advertised 95 rows and two columns. Control/raw snapshots contained only the grid, DataPanel and hidden SearchPanel. Indexed requests returned 60 null cells; hit testing reached the grid and panel, not an overlay. No paired rows or PON were readable, even after scrolling to the bottom. The attachment is not committed because it can contain live order data.

Choosing a window was working. The missing information was in the accessibility provider below that window. This is consistent with, but does not prove, DevExpress clearing its automation peers. [DevExpress documents that behavior](https://docs.devexpress.com/WPF/DevExpress.Xpf.Core.ClearAutomationEventsHelper.IsEnabled) and says the screen-reader parameter prevents clearing. [Microsoft documents the parameter](https://learn.microsoft.com/en-us/windows/win32/winauto/screen-reader-parameter) and its [SystemParametersInfo flags](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow).

The new fallback runs automatically only after an empty initial read from a two-column grid with advertised rows. A temporary helper requests accessibility support, then the reader reacquires the sole visible E-Rx detail grid inside the same entry window, requests focus when supported, and retries normal UI Automation reading. The existing bounded indexed, settled-scroll and hit-test fallbacks remain available. Normal readable grids retain the fast path.

The temporary helper owns a session mutex and the parameter's original value. It does not write the user profile or launch Narrator. An already-enabled parameter remains enabled. A parameter it enables is restored on completion, failure, parent exit, pipe closure or its 40-second limit. The parameter applies to the Windows desktop while active; other Framework instances are not scanned or scrolled. Diagnostics schema 7 records activation, cleanup, refreshed peer identity and whether row text returned. Failure to confirm cleanup produces a warning.

Native Windows regression cases model a grid becoming unreadable within the same remembered window, repeat detection after restoration, an unrelated open E-Rx, provider failure, an already-enabled parameter, permanently empty cells and abrupt parent death with an open pipe. These synthetic tests validate the recovery mechanism, not the actual vendor screen. The next on-site detection establishes whether this recovers this Framework release. If it remains empty, the UI directs the technician to reopen just the E-Rx detail screen and export the existing detection report.
