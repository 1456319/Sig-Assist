# Framework entry-point map — November 19, 2026

First-pass static map, not a live integration implementation or a complete API route catalog. Re-read 12 decompiled C#/XAML artifacts from installer branch commit `54492b1d148ae844aa6442c98480e029ba3a57de` (Framework installer 3.3.363). The branch also contains extracted binaries, many as Git LFS pointers; this is not a complete checked-out C# source tree. No pharmacy process, endpoint or patient data was accessed. FWDirect remains excluded.

The [machine-readable inventory](framework-entrypoints-2026-11-19.json) records source checksums, 56 named control declarations/bindings and 43 direct request call sites. These are **not 43 callable HTTP endpoints**. Reproduce it with `scripts/audit-framework-entrypoints.py --source-root <selected-source-directory> --source-commit 54492b1d148ae844aa6442c98480e029ba3a57de --output <inventory.json>`. Sources are under [installers at the pinned revision](https://github.com/1456319/Sig-Assist/tree/54492b1d148ae844aa6442c98480e029ba3a57de/installers).

**Selector correction:** many XAML controls declare `AutomationProperties.Name`, not `AutomationId`. A WPF Name or view-model property is also not proof of the live provider's AutomationId. The inventory preserves the declaration kind. Test Name/role/Value/Text/Selection patterns inside the unique active page; do not blindly add these strings to an AutomationId-only selector. Provider events and visible-child/offscreen-wrapper behavior still need the dummy-workstation check.

**Character-budget detail:** ordinary vendor preview uses a three-character split separator, whereas our provisional combined-part estimator joins parts with one space. Reconcile this with actual site preview, including the structured-preview branch, before claiming exact multi-part expanded length. Keep the user's shared 199 limit and editable over-budget handling.
